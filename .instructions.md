## Snake God - Agent Rules & Guidelines

### Code Standards
- **Language**: TypeScript (strict mode enforced)
- **Target**: ES2020+
- **Module System**: ESNext with proper module resolution
- **Build Tools**: Use `esbuild` for compilation and bundling
- **Package Manager**: npm

### Preferred Dependencies (Nuxt Team Ecosystem)
When adding utilities and tools, prefer packages from the Nuxt/Vue ecosystem:
- `@unhead/vue` - Head management (if adding SSR features later)
- `consola` - Better logging
- `devalue` - Serialization utilities
- `h3` - HTTP framework (if adding backend)
- `nitro` - Server framework (if expanding to fullstack)
- `pathe` - Path utilities
- `scule` - String utilities

### Architecture Principles

#### Class Structure
- Use TypeScript classes for game entities (`Card`, `Deck`, `Snake`, `GameManager`)
- Maintain single responsibility principle
- Encapsulate state with private fields
- Use getters/setters for property access

#### State Management
- Implement explicit state machine (PLANNING → ACTION → TRANSITION)
- Use event emitter pattern for UI synchronization
- Avoid global state; pass through constructor or methods
- Console log all state transitions for debugging

#### UI Pattern
- Keep UI rendering separate from game logic (UIRenderer class)
- Use event listener callbacks for reactivity
- Maintain pixel-art aesthetic with CSS (`image-rendering: pixelated`)
- Use CSS variables for theming
- Responsive design mobile-first approach

### File Organization
```
src/
  ├── card.ts           # Card entity
  ├── deck.ts           # Deck management
  ├── snake.ts          # Snake entity
  ├── game-manager.ts   # State machine & core logic
  ├── ui.ts             # UI renderer
  └── index.ts          # Entry point & initialization
```

### Build & Development
- Run `npm run build` to compile TypeScript with esbuild (one-time)
- Run `npm run dev` to start development server with HMR on http://localhost:8000
- Run `npm run watch` for file watching without HTTP server
- Output compiled files to `dist/` directory
- Always generate source maps for debugging
- **Volta** pins Node.js and npm versions per project (configure in package.json)

### Git & Commits
- Do NOT commit or push changes until explicitly approved after testing
- Write clear commit messages with scope: `feat(card):`, `fix(ui):`, etc.
- Test all changes locally before requesting review

### Documentation
- Include JSDoc comments on all public methods
- Document complex algorithms and state transitions
- Keep README.md updated with feature changes
- Document breaking changes prominently

### Performance Considerations
- Avoid re-rendering entire UI on every state change
- Use event-driven updates from GameManager
- Lazy load card data if deck grows large
- Profile animation performance on pixel rendering

### Testing
- Create unit tests for Card, Deck, Snake classes
- Test state transitions in GameManager
- Validate color morphing calculations
- Test card swap logic edge cases

### Code Quality
- Enforce TypeScript strict mode
- Use const/let (no var)
- Prefer arrow functions for callbacks
- Use template literals for strings
- Comment non-obvious logic

### Naming Conventions
- Classes: PascalCase (`GameManager`, `UIRenderer`)
- Functions/Methods: camelCase (`startTurn()`, `swapCards()`)
- Constants: UPPER_SNAKE_CASE (`PLANNING`, `MAX_HEALTH`)
- Private fields: prefix with `_` (or use `private` keyword)
- Card types: UPPER_SNAKE_CASE (`VENOM`, `CONSTRICT`, `MOLTING`)
